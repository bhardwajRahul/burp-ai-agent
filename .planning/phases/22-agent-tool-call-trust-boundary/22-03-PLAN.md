<objective>
Create the AWT-free half of the SEC-06 gate: one shared canonicalisation function, the `ToolCallOrigin`
sealed type whose model-approved variant only the gate can mint, the `ToolDecision` vocabulary, and
`tierFor(rawToolName)`.

Two failure modes this plan exists to prevent, both measured by research:

- **The gate reads a different tool name than the executor.** `resolveAlias` is `private` in
  `McpToolExecutor` and maps ten alias inputs onto four canonical IDs, all four of which are `CONFIRM`.
  A gate that does not canonicalise labels every alias "unknown", mislabels the card, corrupts the
  audit `toolName`, and makes the tier lookup fall through. Copying the map creates exactly the
  two-lists-to-keep-in-sync shape D-03 rejected. One exposed function, both sides call it.
- **A future fourth parse-and-execute call site silently inherits the ungated path.** CONTEXT left the
  SC5 mechanism to research and planning with an explicit instruction to confirm rather than assume.
  Research confirmed the parameter belongs on `executeTool` and **refuted** `McpToolContext` (it is also
  constructed by `McpRuntimeContextFactory` for the MCP-server runtime, which has no chat origin at
  all). This plan goes one step further than the CONTEXT recommendation, per the maintainer's stated
  standard that *a control a future edit can silently undo is not a control*: the model-originated
  variant is **file-private to the gate's own file**, so it cannot be constructed anywhere else.

Purpose: SEC-06 / SC5 (structurally distinguishable origins), SC6 (`ext:` derivation and fail-closed
unknown); D-04, D-05 runtime fallback.
Output: `McpToolExecutor.canonicalToolId`, `mcp/ToolApprovalGate.kt` (types + `tierFor`), and
`SecTierResolutionTest`.

**Scope boundary:** the decision state machine, session memory, the denial constant and iteration
accounting land in plan `22-04`, in this same file. Do not build them here.
</objective>

Create `src/main/kotlin/com/six2dez/burp/aiagent/mcp/ToolApprovalGate.kt`, package
`com.six2dez.burp.aiagent.mcp`.

**Deliberate deviation from `22-PATTERNS.md`, which lists `ToolCallOrigin.kt` and `ToolApprovalGate.kt`
as two files: they are ONE file here, and the reason is load-bearing.** Kotlin `internal` is module-wide
(the whole `main` source set), so an `internal` factory does not bind minting to the gate. The only
compile-time mechanism that does is **file-private visibility**, which requires the origin
implementation and the gate to be declared in the same file. Record this in the file header.

**File header comment** — mirror `McpAccessControlDecision.kt:8-13` in shape. Required content:
(a) SEC-06 / ADR-15: the pure decision half of the tool-call trust boundary;
(b) everything is `internal` rather than `private` so `ToolApprovalGateTest` and `SecTierResolutionTest`
can reach it without reflection — the same test-seam convention as `redact/Redaction.kt:215-228`;
(c) **no `javax.swing` and no `java.awt` import appears in this file**, and that is what keeps the
SEC-06 decision provable without a Swing harness.

Declare four things:

**1. `enum class ToolDecision(val wireValue: String)`** — the vocabulary both the audit payload and the
UI read, defined once so the two sinks cannot disagree (the `BlockReason` convention). Constants and
wire strings, exactly:
`APPROVE_ONCE("approve_once")`, `APPROVE_SESSION("approve_session")`, `DENY("deny")`,
`DENY_SESSION("deny_session")`, `AUTO("auto")`, `SESSION_APPROVED("session_approved")`,
`SESSION_DENIED("session_denied")`, `IMPLICIT_DENY("implicit_deny")`.
KDoc must explain the pair that matters to an auditor: `APPROVE_ONCE` means a human clicked *for this
call*; `SESSION_APPROVED` means an earlier click was applied without asking. Collapsing them would make
"did a human authorise this specific invocation" unanswerable from the log.

**2. `enum class ImplicitDenyReason(val wireValue: String)`** — `NEW_MESSAGE("new_message")`,
`SESSION_DELETED("session_deleted")`, `CHAT_CLEARED("chat_cleared")`,
`PROJECT_CHANGED("project_changed")`, `UNLOAD("unload")`. Research measured **five** teardown paths, not
D-08's three; plan `22-08` wires all five. Declaring the enum here means the audit shape is fixed before
the wiring exists.

**3. `sealed interface ToolCallOrigin`** with `val wireValue: String`, and two public variants declared
inside it: `data object UserDialog` (`"user_dialog"` — the user picked the tool and typed the args in
`ToolInvocationDialog`, `ChatPanel.kt:928`) and `data object UserSlashCommand` (`"user_slash_command"` —
the user typed the `/tool` slash command, `ChatPanel.kt:2105`).

The model-originated variant is a **top-level `private class`** in this same file — for example
`private class ModelApproved(val tier: SecTier, val decision: ToolDecision) : ToolCallOrigin` with
`wireValue = "model_approved"`. Because it is top-level `private`, it is visible only inside
`ToolApprovalGate.kt`; no other file in the module can construct it or name its type. A sealed
interface permits implementations in the same package and module, so this compiles. Expose it only
through an internal gate function that returns the **interface** type, e.g.
`internal fun ToolApprovalGate.approvedOrigin(tier: SecTier, decision: ToolDecision): ToolCallOrigin`.
Callers pass the value on; they never name the type.

Put a KDoc on the interface stating the property in plain English: *a hypothetical fourth
parse-and-execute call site cannot compile without obtaining a model origin from this gate, which means
going through the decision. A plain enum would let it write `origin = MODEL` and silently reopen
SEC-06.*

**Fallback, if and only if the top-level-private-class form does not compile** (for example if the
Kotlin version in use restricts sealed-interface implementations further than expected): use
`class ModelApproved internal constructor(...)` plus a KDoc contract naming this file as the only
sanctioned construction site, and record in the plan SUMMARY which form shipped and the exact compiler

with `McpToolCatalog.all().firstOrNull { it.id == canonical }` — the same lookup shape

The `?:` branch needs its own comment: *fail closed. D-03 removes the AUTHORING default; this is the
RUNTIME fallback it does not cover. An unrecognised name must never resolve to `AUTO`.*

Add the gate's purity KDoc in the shape of `McpAccessControlDecision.kt:103-114`: pure by contract — no
logging, no audit events, no I/O, no side effects. Audit emission is a separate call the `ChatPanel`
caller makes from the resolved branch (plan `22-05`'s `ToolDecisionReporter`). State explicitly that
**Phase 20 D-09 aggregation-based rate limiting is deliberately NOT applied here**: the flood vector
there was a remote unauthenticated peer, whereas here the ceiling is `MAX_AUTO_TOOL_ITERATIONS = 8` per
chain and D-13 makes the counter monotone. Saying so is better than an unexamined omission.

**5. The two text sanitizers (`22-UI-SPEC.md` Rule T-6).** They land here, in the AWT-free file,
because **both** plan 22-05's audit reporter and plan 22-06's Swing card consume them and they run in
the same wave — a second, subtly different copy of a shipped control is the failure mode this phase
exists to avoid. Copy the idiom from `mcp/McpBlockedRequestReporter.kt:21-27, 220-233`; do not
re-derive the regex. Two `internal` top-level functions:

- `internal fun sanitizeInline(value: String?, maxLength: Int = 120): String?` — removes control
  characters with `Regex("[\\p{Cntrl}\\u0080-\\u009F]")`, collapses `\s+` to a single space,
  trims, and truncates to `maxLength` with a `…` suffix. Used for the model-supplied **tool ID** on the
  card, in the accessible description and in the audit payload.
- `internal fun sanitizeBlock(value: String?, maxChars: Int, maxLines: Int): String` — removes control
  characters **except `\n` and `\t`**, preserves line structure, and truncates by whichever of the two
  caps bites first. Used for the **args JSON** in the card's expandable preview.

Two KDoc facts must be recorded, both from the analog: control characters are **REMOVED, never
replaced**, so `"a\r\nInjected: line"` collapses to `"aInjected: line"` and a forged second log line is
impossible (CWE-117); and Java's `\p{Cntrl}` covers only `\x00-\x1F` and `\x7F` unless
`UNICODE_CHARACTER_CLASS` is set, which is why the C1 range `\u0080-\u009F` is spelled out.

Record why there are two: `\p{Cntrl}` includes `\n` and `\t`, so the inline sanitizer applied to args
would flatten JSON into one unreadable line — the opposite of D-07's "full args are shown because the
args are where exfiltration hides" — while the block sanitizer applied to a tool ID would let a name
like `"scope_check\n\n✔ Approved"` occupy several lines and imitate an outcome row.

Do not add the session-memory holder, `evaluate`, the denial constant or the outcome type — plan
`22-04` adds them to this file.
