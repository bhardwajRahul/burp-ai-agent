This is the plan that closes SEC-06. Everything before it built parts; this one puts the gate in the
path.

`ChatPanel.maybeExecuteToolCall` (`:2114-2197`) currently takes `ToolCallParser.extractFirst` output and
calls `McpToolExecutor.executeTool` at `:2132` with nothing between them but the per-tool toggles and
the `unsafeOnly` flag. Model context contains attacker-controlled data — proxy traffic sent via "Send to
AI", passive-scan findings and external MCP tool results — so tool *selection* is attacker-influenceable.
After this plan a non-`AUTO` model-originated call cannot reach Burp until the user clicks.

Two structural changes, both deliberate:

- **`executeTool` gains a required, non-defaulted `origin`.** CONTEXT left the SC5 mechanism open with an
  instruction to confirm rather than assume; research confirmed the parameter belongs here and refuted
  `McpToolContext` (also built by `McpRuntimeContextFactory` for the MCP-server runtime, which has no
  chat origin). `executeToolResult`'s signature does **not** change, which is what keeps
  `McpToolHandlers.kt:129` and the whole MCP-server path compiling untouched.
- **`maybeExecuteToolCall`'s `Boolean` becomes a three-valued outcome.** `AWAITING_DECISION` parks
  `onCompleted` in the pending record instead of invoking it. Nothing about *where* `executeTool` runs
  changes — it is still on the EDT, and Phase 23 / REL-05 owns moving it. Report EDT problems for
  Phase 23; do not fix them here.

**Intentional intermediate state between Task 1 and Task 2.** Task 1 consults the gate and treats
`Ask` as a denial — a strict, fail-closed, shippable state. Task 2 supplies the card that turns `Ask`
into a real decision. Build them in that order; do not merge them.

**Scope boundary — do NOT add here:** the five implicit-denial teardown paths, the SC3 audit emission,
the session-list pending marker and `scrollToComponent` all land in plan `22-08`. In particular do not
add ad-hoc `pending.clear()` calls at teardown sites; `22-08` introduces one `resolvePending` entry
point and an ad-hoc hook would have to be unpicked.
