<objective>
Build the SC3 record: one reporter that turns a resolved SEC-06 decision into an ordered `AuditLogger`
payload, one human-visible Burp Output line, and the metadata map `ChatPanel` merges into its existing
`ActivityType.MCP_TOOL_CALL` emission.

The shape **extends** what already ships. `ChatPanel.kt:2158-2174` already emits `operation` / `status` /
`traceId` / `step` / `toolName` / `resultChars`; `McpTool.runTool` already emits
`mcp_tool_start` / `mcp_tool_end` / `mcp_tool_blocked` to `AuditLogger.emitGlobal` for every tool call.
Both destinations Phase 20 D-06 requires therefore already exist — they simply do not carry the SEC-06
decision. This plan adds the four missing fields (`secTier`, `decision`, `implicitDenyReason`,
`argsSha256`), the third `status` value (`denied`), and the Output-tab line.

Splitting the reporter out of `ToolApprovalGate` is the repo's own established shape for a security
gate: `mcp/McpAccessControlDecision.kt` decides and `mcp/McpBlockedRequestReporter.kt` reports, and that
separation is what makes every row of the access-control matrix assertable with no server and no clock.
The same separation here means the tier table and the state machine stay provable without an audit sink.

Purpose: SEC-06 / SC3 (every decision written to the audit log with the tool name, the decision and the
chain step, consistent with the existing `MCP_TOOL_CALL` shape); Phase 20 D-06 and D-10 inherited.
Output: `mcp/ToolDecisionReporter.kt` and `ToolDecisionReporterTest`.
</objective>

**File header comment**, in the shape of `McpBlockedRequestReporter.kt:8-14`. It must state that the
audit type constant is **new** — `mcp_tool_decision` — and must not be a reuse of `mcp_tool_blocked` or
`mcp_tool_end`, because a constant whose payload keys carry different meanings corrupts downstream
analysis. Name SEC-06 / SC3 / ADR-15.

**Class shape:** `internal class ToolDecisionReporter(private val logToOutput: (String) -> Unit, private val verboseAudit: Boolean = false)`.
Copy the analog's KDoc reasoning for both seams: the output sink is a lambda rather than a `MontoyaApi`
so tests capture into a list without a Mockito deep stub; `verboseAudit` is a constructor seam wired to
`false` because `AgentSettings` still has `auditEnabled` but **no** verbose-audit flag anywhere in the
repo (verified this phase), and adding one is explicitly out of scope for SEC-06.

**`private const val MCP_TOOL_DECISION_EVENT = "mcp_tool_decision"`.**

**One reporting entry point:** `internal fun report(...): Map<String, String>`, taking, in order —
`rawToolName: String`, `canonicalId: String`, `knownTool: Boolean`, `tier: SecTier`,
`decision: ToolDecision`, `argsJson: String?`, `traceId: String`, `chainStep: Int`,
`implicitDenyReason: ImplicitDenyReason? = null`, `resultChars: Int? = null`, and (per the `status`
rule below) `runStatus: String? = null`.

It performs both emissions and **returns** the `AiRequestLogger` metadata map so `ChatPanel` merges one
map built here rather than assembling a second, subtly different one at the call site. Returning the map
is the mechanism that stops the two sinks drifting — the same instinct as plan 22-03's single
canonicalisation function.

**Payload construction** — a `linkedMapOf` so key order is assertable, in exactly this order:

1. `"operation"` → `"tool_chain"` (plaintext, unchanged from today)
2. `"status"` → `statusFor(decision, resultChars)`: `"denied"` for `DENY`, `DENY_SESSION`,
   `SESSION_DENIED` and `IMPLICIT_DENY`; otherwise the caller's existing `"ok"` / `"error"` derivation
   is preserved — pass it in via `resultChars` being non-null for a run and let the caller supply the
   error case. Simplest correct rule to implement: add a `runStatus: String?` parameter defaulting to
   `null`, use `"denied"` whenever the decision is one of the four denial values, and otherwise use
   `runStatus ?: "ok"`. Document the D-12 reason: denial is a policy outcome, not a malfunction.
3. `"traceId"` → plaintext, extension-derived
4. `"step"` → `chainStep.toString()`
5. `"toolName"` → when `knownTool` is true, the **canonical** ID in plaintext (it came from the catalog,
   so it is extension-derived and not attacker-controlled); when false, the literal `"unknown"`
6. `"toolNameSha256"` → present **only** when `knownTool` is false:
   `Hashing.sha256Hex(sanitizeInline(rawToolName).orEmpty())`. An uncanonicalisable name is
   model-controlled, so it is hashed rather than written plaintext into the persistent record.
7. `"secTier"` → `tier.wireValue`, plaintext, **on every event including `AUTO`**
8. `"decision"` → `decision.wireValue`, plaintext
9. `"implicitDenyReason"` → present **only** when `decision == ToolDecision.IMPLICIT_DENY`, value
   `implicitDenyReason?.wireValue`
10. `"argsSha256"` → present **only** when `argsJson` is non-blank; value
    `auditValue(argsJson)` where `auditValue` is the analog's one-liner —
    `sanitizeInline(value)?.let { if (verboseAudit) it else Hashing.sha256Hex(it) }`. Null in, null out:
    never hash the empty string, or "absent" and "empty" become indistinguishable.
11. `"resultChars"` → present **only** when `resultChars` is non-null; a denial has no result

Emit it once: `AuditLogger.emitGlobal(MCP_TOOL_DECISION_EVENT, payload)`.

**Output-tab line** — exactly one line per invocation, via `logToOutput`. It carries **sanitized
plaintext, never a hash**, because the Output tab is where a human diagnoses. Format, single line, all
extension-derived except the last field:

`[SEC-06] decision={decision.wireValue} tier={tier.wireValue} tool={canonical or sanitized raw} step={n} trace={traceId}`

For an unknown tool use `sanitizeInline(rawToolName)` for the `tool=` field — control characters removed,
whitespace collapsed, capped at 120 characters — so a model-authored newline cannot forge a second
Output line (CWE-117). Never interpolate raw `argsJson` into the Output line.

**Returned metadata map** — a `Map<String, String>` built from the same payload with null values
dropped and every value already a `String`, so `ChatPanel` can write
`metadata = existingMap + reporter.report(...)`. Because both come from one construction, the audit
event and the AI Activity record cannot disagree.

**Two things to state explicitly in KDoc rather than omit** (research called both out):

- **No rate limiting.** Phase 20 D-09's aggregation is deliberately not applied: the flood vector there
  was a remote unauthenticated peer, whereas here the ceiling is `MAX_AUTO_TOOL_ITERATIONS = 8` per
  chain and D-13 keeps the counter monotone.
- **No settings toggle for `verboseAudit`.** It stays a constructor seam wired to `false`; adding a
  user-facing verbose flag is not in SEC-06 and Phase 20 explicitly declined it.

The reporter performs no policy: it never decides, never consults session memory, and never calls the
gate. It is invoked from the caller's already-resolved branch.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Model-authored tool name and args → persistent audit record | Attacker-influenceable text crossing into a durable log. Log injection (CWE-117) and confidentiality both apply. |
| Extension → Burp Output tab | The human-visible diagnostic surface. It carries plaintext by design, so it needs the sanitizer rather than the hash. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-06 | Tampering / Repudiation | Model-authored tool name or args written into the audit payload or the Output tab (CWE-117 log injection) | mitigate | `sanitizeInline` removes control characters rather than replacing them, collapses whitespace and caps at 120 characters before either sink; `outputLineIsSingleLineAndSanitized` asserts a forged second line is impossible. |
| T-22-09 | Repudiation | A SEC-06 decision that is not recorded, or recorded only where nobody looks | mitigate | Phase 20 D-06 dual destination: `AuditLogger.emitGlobal("mcp_tool_decision", …)` **and** the returned `MCP_TOOL_CALL` metadata map **and** one Burp Output line, because audit logging is disabled by default in this project. |
| T-22-23 | Information Disclosure | Model-supplied args written to a durable log in plaintext, leaking target data into the audit trail | mitigate | Phase 20 D-10 + CLAUDE.md: `argsSha256` is `Hashing.sha256Hex` by default, plaintext only behind the `verboseAudit` constructor seam which is wired to `false` and has no user-facing toggle. Asserted by marker-absence. |
| T-22-19 | Tampering | A denial recorded as `status = "error"`, making a policy decision indistinguishable from a malfunction | mitigate | `"denied"` is a third status value; asserted for all four denial decisions. |
| T-22-24 | Repudiation | An `AUTO`-tier call being indistinguishable in a historical log from a pre-fix decision-less call | mitigate | `secTier` is emitted on every event, including `AUTO`. |
| T-22-25 | Tampering | Reusing an existing audit type constant whose payload keys mean something different | mitigate | New constant `mcp_tool_decision`; asserted by grep that `mcp_tool_blocked` / `mcp_tool_end` do not appear in the reporter. |
| T-22-SC | Tampering | npm/pip/cargo installs | accept | Zero packages added — `22-RESEARCH.md` §"Package Legitimacy Audit" records an empty table. Any deviation requires running the Package Legitimacy Gate first. |
