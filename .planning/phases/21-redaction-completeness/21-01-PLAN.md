<objective>
Wave 0 for Phase 21. Extract three mechanical, Montoya-free functions out of
`PassiveAiScannerAnalysis.doAnalysis` into `PassiveAiScannerPrompts.kt`, and create the test file that
later plans extend with the SC1 / SC2 / D-06 end-to-end assertions.

`doAnalysis` needs `HttpRequestResponse`, `HttpRequest`, `HttpResponse`, `MontoyaApi`, a backend session
and `ScanKnowledgeBase` state — it is not unit-testable. The PRIV-05-relevant logic inside it is 100%
plain-`String` transformation. Moving that logic out is what lets `/gsd-verify-work` prove SC1 and SC2
against the **real emitted blob format** rather than a hand-written string, which is precisely the gap
that let PRIV-05 ship.

This plan changes no redaction behaviour. It only relocates code and deletes one short-circuit
(D-06, scanner half) that is behaviour-preserving today and becomes load-bearing when D-05 lands in
plan 21-06.

Purpose: PRIV-05 (make the leak assertable at its source), PRIV-06 / D-06 (delete the caller-side OFF
bypass so OFF is a policy in one place).
Output: three `internal fun`s in `PassiveAiScannerPrompts.kt`, a rewired `doAnalysis`, and
`PassiveAiScannerPromptRedactionTest.kt`.
</objective>
