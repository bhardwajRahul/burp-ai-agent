<objective>
Close the four cookie-rule findings of `21-REVIEW-2.md` that can each silently reopen a leak this
phase already closed, and dispose of the fifth deliberately:

- **W-01** — `MAX_COOKIE_SECTION_LINES = 16` silently *stops redacting* past line 16 (verified live:
  entries `ck16`…`ck19` of a 20-entry section reach the output verbatim). Nothing couples it to
  `COOKIES_MAX_COUNT = 6`, which lives in another file, in another package, under a name that gives no
  hint the redactor depends on it. Raising that one constant reopens PRIV-05 for every entry past the
  sixteenth **with the entire suite green**. This is the same failure mode the phase has already paid
  for twice: an unasserted coupling between an emitter constant and a redactor rule.
- **W-03** — `sanitizeCookieSectionEntries` has **zero** direct tests. Its middle limb is the one its
  own KDoc calls load-bearing, and deleting `.replace('\r', ' ').replace('\n', ' ')` leaves the whole
  suite green while CR-01's second trigger is reopened in full. Asked the standing question — what
  else in the pipeline would catch this input? — the answer for that limb is *nothing*.
- **W-05** — `COOKIE_SECTION_BUDGET_MS` is documented as bounding the function "across ALL
  occurrences" but is sampled only *between* header occurrences, so it does not bound what it claims;
  and because the check precedes `indexOf`, a stop-the-world pause causes **the entire remaining
  prompt** — up to 2 MiB by default — to be replaced by one drop marker even when no further cookie
  section exists. That fails closed, so it is not a leak; it is a silent total loss of analytic
  context on a well-behaved input, triggered by nothing the user did.
- **W-07 (KDoc half)** — `sanitizeCookieSectionEntries`'s KDoc still says "Nothing in plan 21-08 calls
  this yet". Plan 21-10 wired it at two sites. A KDoc on a security control stating the control is
  unused is actively misleading, and this codebase uses "the named guard is X" comments as a
  load-bearing safety mechanism, so a wrong one devalues all of them.
- **W-02** — a planted `=== COOKIES ===` now blinds a fixed 16 lines of an attacker's own response
  body regardless of blank lines. **Disposition to be recorded deliberately, with its argument**, not
  left implicit.
- **IN-04** — `sanitizeCookieSectionEntries` runs twice on the production path, idempotently. Recorded
  so it is not later "cleaned up" by removing whichever call the reader notices first.

Purpose: PRIV-05 is the requirement this phase exists for, and every item above is a way it silently
comes back. Locked decisions in force: **D-09** (redact every cookie value in the section), **D-10**
(iterate every occurrence — a security requirement with a demonstrated exploit), **D-02** (fail
closed).

Output: the emitter bound coupled to the redactor's, three previously-unguarded mechanisms guarded,
one fail-closed overreach corrected, and four records made true.
</objective>
