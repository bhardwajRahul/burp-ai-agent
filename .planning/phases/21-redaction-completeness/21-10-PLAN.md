<objective>
Wire `Redaction.sanitizeCookieSectionEntries`, exported by plan 21-08, into the two places that build the
cookie section. This closes CR-01's **second trigger**: a cookie element beginning with `=== ` truncates
the section span and every cookie after it leaks.

**Why this half is not in the redactor.** Plan 21-08 fixed the span bound so blank entries can no longer
collapse or truncate the span, and that is the fix for the dominant, uncrafted case. The section-header
shape is different in kind: the span terminator is necessarily derived from content **inside** the region
the rule protects, which is in-band signalling. No redactor-side rule can distinguish `=== FOO ===`
planted in a cookie value from the genuine `=== PARAMETERS ===` that must terminate the span — and the
`=== ` terminator cannot simply be dropped, because without it the section swallows the parameters
section and `q=red running shoes (URL)` gets redacted as a cookie. The only place the two are
distinguishable is where the frame is written. So the framing is made unforgeable at the emitter, and the
sanitizer lives in `redact/` next to the rule that depends on it, exactly as `COOKIE_SECTION_HEADER`
does — a future edit that removes the call deletes a named control with a named test, not an incidental
`.filter {}`.

Plan 21-08 already pinned the residual with `cookieSectionHeaderShapedEntryTerminatesSpan_documentedResidual`,
which asserts the redactor-level behaviour and is green before and after. That test **stays as it is** —
it documents the boundary of the redactor's reach. This plan adds the end-to-end guard that proves the
combined pipeline is closed.

This plan touches only `scanner/` sources and the scanner test, so it is file-disjoint from plan 21-09 and
runs alongside it in wave 2.

Purpose: PRIV-05, CR-01 second trigger, D-09, D-10, SC1.
Output: the sanitizer wired at both cookie-section build sites, plus the poisoned-header end-to-end guard.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| target HTTP request `Cookie:` header -> `=== COOKIES ===` section | the raw header value is split on `;` and each element becomes a line in a structured prompt section. The value is attacker-influenceable (a target can set cookies on the victim's browser) and the victim's own session material sits in the same list |
| prompt section framing -> `Redaction.redactCookieSections` | the redactor's span bound reads the framing back out of the emitted text, so anything that can write a line can influence where the span ends |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-32 | Information disclosure | in-band section framing forged from a cookie value | mitigate | **CR-01's second trigger.** A cookie element beginning with `=== ` truncates the span and every cookie below it leaks. Closed at the emitter, which is the only point where a real section header and a planted one are distinguishable, via the `redact/`-owned `sanitizeCookieSectionEntries`. Guards: `poisonedCookieHeaderCannotTerminateTheCookieSection` (behaviour) and `cookieSectionEntriesAreSanitizedAtTheEmitter` (framing) |
| T-21-20 | Tampering (silent control drift) | a future edit removing the sanitizer call | mitigate | The sanitizer is owned by `redact/`, not written inline in the scanner, exactly as `COOKIE_SECTION_HEADER` is; the call site comment names the leak it prevents and the test that guards it; the mutation check in the acceptance criteria proves the tests actually fail without it |
| T-21-16 | Information disclosure | cookie values reaching the backend (PRIV-05 / F2) | mitigate | Unchanged from plan 21-05 and re-asserted end-to-end here against the real emitted blob rather than a hand-written string |
| T-21-06 | Denial of service (of the product's value) | sanitisation discarding analytic content | mitigate | Only genuinely empty entries are dropped. | T-21-SC | Tampering | npm/pip/cargo installs | accept | Zero packages installed; no new Gradle dependency; `scanner/` gains no import beyond the existing `redact` package |
