**`windowEnd(s: String, start: Int, width: Int): Int`** — returns the index just past the last newline
at or before `start + width`. A single line longer than `width` becomes its own oversized window rather
than being split: every built-in body rule is line-anchored or line-local, so a mid-line cut is the only
way to change their semantics. This is not defensive coding — naive `substring` windowing was
demonstrated to corrupt `(?m)^` in both directions (a mid-line cut both creates matches that should not
exist and truncates matches that should). `Matcher.region()` has the correct semantics but
`Matcher.replaceAll()` silently resets the region, so region-based replacement is not available at all.
Include the JSON boundary-safety rule: `jsonSecretKeyRegex`'s whitespace class can span newlines, so if
the last line of the prospective window ends with a colon or a double quote after trailing-whitespace
strip, pull in one more line. `formBodyParamRegex` and `urlTokenParamRegex` cannot span newlines and
need nothing.

**`scanWindow`** — apply each rule to the window via `SafeRegex.replaceAllSafeReporting` with
`timeoutMs = minOf(SafeRegex.DEFAULT_TIMEOUT_MS, remainingBudgetMs)`. The `minOf` is what prevents
double-counting: a per-pattern deadline can never outlive the total budget, so a rule starting with
12 ms of budget left gets a 12 ms deadline and *reports* a timeout rather than overrunning. If
`timedOut` is true, or the budget runs out mid-window, do **not** append anything from that window —
hand off to the halve-and-retry path. Only a fully scanned window is appended.
**Never assign `replaceAllSafe`'s return value here.** On timeout it returns the input unchanged,
indistinguishable from "no matches"; a body stage built on it is fail-**open** at exactly the moment
D-02 demands fail-closed.

**Halve-and-retry.** On a window timeout, split the window at a line boundary and retry each half, to a
maximum depth of `WINDOW_RETRY_MAX_DEPTH = 2`, before dropping. Measured justification: dense form
content at 1 MB costs 23 ms on Apple Silicon against a 50 ms deadline — only ~2.2x headroom, so a
2-3x slower machine would drop content that ships today. This turns the deadline into a pacing
mechanism instead of a cliff. If the window cannot be split (no interior newline, or the computed cut
is 0 or the full length), drop immediately rather than recursing. On drop, append the
window-level marker and call `maybeLogTruncation`.

**Marker strings** — two constants, ASCII hyphen (not an em dash: the marker is prompt content that
gets hashed into `sha256Hex(singlePrompt)` and round-trips through backend transports):
`[REDACTION BUDGET EXCEEDED - <n> CHARS DROPPED AND NOT SENT]` for the budget-exhausted tail and
`[REDACTION INCOMPLETE - <n> CHARS DROPPED AND NOT SENT]` for one dropped window, where `<n>` is a
plain integer. Document the four properties the wording must keep: it says the content was **removed**,
not passed through (D-03's suggested `[TRUNCATED — NOT REDACTED]` reads as the opposite of what
happened); it is distinguishable from `[REDACTED]` so a reader can tell "removed for size" from
"removed for secrecy", the same reason `[JWT_REDACTED]` and `[STRIPPED]` are distinct tokens today; it
is a constant shape plus one integer, so it contains **zero** attacker-controlled substring and is not
an injection vector; and it is not phrased as an instruction to the model.
