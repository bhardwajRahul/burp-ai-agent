<objective>
Close W-A from `21-VERIFICATION.md`: widen the two cookie header regexes so a header whose NAME
contains `cookie` is stripped, while preserving the original header name in the output.
</objective>

<threat_model>
| ID | STRIDE | Threat | Disposition | Mitigation |
|----|--------|--------|-------------|------------|
| T-21-WA1 | Information disclosure | A cookie-bearing header whose name is not literally `Cookie`/`Set-Cookie` reaches an AI backend verbatim under STRICT/BALANCED. Measured on five real names. | mitigate | Match on name-contains-`cookie` rather than exact name. |
| T-21-WA2 | Tampering | Widening the match with a fixed replacement string silently renames headers in the prompt, corrupting the analyst's view of the traffic. | mitigate | Preserve the matched name, mirroring `authHeaderRegex`. |
| T-21-WA3 | Denial of service (utility) | Over-redaction of a benign header merely containing `cookie` in its name. | accept | Any `*cookie*` header is cookie-bearing by convention; the value is the only thing removed. |
</threat_model>
