<objective>
Close the three warnings of `21-REVIEW.md` that plan 21-12 deliberately deferred and that
`21-REVIEW-2.md` re-raised, one of them with increased exposure.

**WR-03 — the fail-open footgun.** `SafeRegex.replaceAllSafe` has **zero** production callers; the
reviewer re-verified this in round 2. What remains is a `public` function in the redaction package
whose own KDoc says it is fail-open and "conflates 'matched nothing' with 'timed out'" — precisely the
mistake this phase exists to remove, sitting one autocomplete away from the next contributor who adds
a rule. The three comments in `Redaction.kt` that warn against reaching for it are themselves evidence
that the team already anticipates it being reached for.

**WR-07 — the ReDoS gate that only tests one character class.** `isPatternSafe` validates against one
fixed string, `"a".repeat(2_000) + "!"`. A pattern catastrophic on a different character class runs in
microseconds on that probe and is accepted. Before this phase that was tolerable — custom patterns ran
only inside the `redactTokens` branch and a slow one was simply skipped. **D-05 changed both halves.**
Custom patterns now run in **every** privacy mode including `OFF`, and `bodyStage` now fails
**closed**, so an accepted-but-slow pattern no longer degrades gracefully: it burns
`MAX_REDACTION_BUDGET_MS` and causes real content to be dropped behind markers on every call,
including calls the user believes are unfiltered. The blast radius of a bad accept grew in both
directions without the gate being strengthened. `App.kt`'s startup seeding compounds it by trusting
persisted patterns wholesale — Burp preferences are user-editable and may predate `isPatternSafe`.

**WR-04 / W-08 — the teardown race, now wider.** `App.shutdown()` unwires `BackendDiagnostics.retry`,
`AuditLogger`'s global emitter and `Redaction.clearMappings()`, and leaves `Redaction.truncationLogger`
holding a lambda that captures `api`. `maybeLogTruncation` still has no `try`/`catch`, so a throw from
a torn-down `api.logging()` propagates out through `redactCookieSections` → `apply` → the caller. Plan
21-12 deferred this as "a teardown-race robustness issue", which was accurate when written; this phase
then added a **third** call site inside `redactCookieSections`, which runs in the *header* stage of
every `Redaction.apply` where `stripCookies` is true — the default BALANCED mode, on every MCP tool
call and every passive scan, not only on oversized bodies. The teardown window is now reachable far
more often than when the deferral was recorded.

Locked decisions in force: **D-03** (the truncation signal is dual-destination and must never cost
correctness), **D-05** (custom patterns apply in every mode), **D-14** (`replaceAllSafeReporting`'s
`timedOut` flag is the only reliable signal). See the note on D-14 in the constraints — WR-03
supersedes one clause of it by maintainer decision, and that must be recorded rather than glossed.
</objective>
