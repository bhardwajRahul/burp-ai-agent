<objective>
Close SC1 (REL-06): every recurring scheduled task survives a throw in its body. This plan builds the
guard mechanism, routes all three unguarded call sites through it, and installs the structural gate
that stops a fourth unguarded site appearing later.

It also front-loads the phase's shared interface — the new `Defaults` constants and the single
`tasks.test` input declaration every structural assertion in this phase depends on — so plans 24-02
and 24-03 can run in parallel without touching `build.gradle.kts` or `Defaults.kt`.

**This plan must land before any executor in this phase is bounded.** `ActiveAiScanner.processQueue()`
has no test-reachable throw site on the scheduler thread today: everything that can throw already sits
inside the per-target `try/catch` at `ActiveAiScanner.kt:391-401`. Bounding an executor *creates* the
throw site — `exec.submit(...)` at `ActiveAiScanner.kt:391` is outside any `try`, so a bounded pool
makes it throw `RejectedExecutionException` on the scheduler thread and permanently cancel the queue
drain. Doing SC6 without SC1 first makes the scanner strictly worse than it is today. The wave
ordering (this plan is wave 1; 24-02 and 24-05 bound pools in waves 2 and 4) is the encoding of that
coupling.

Purpose: a single exception can no longer silently disable a background subsystem for the rest of a
Burp session.
Output: `util/GuardedScheduling.kt`, two new headless test suites, one `build.gradle.kts` input
declaration, five new `Defaults` constants, three migrated call sites.
</objective>
