<objective>
Close Finding 7 on the credential side (SEC-07, ROADMAP SC1 + SC2): the bind-conflict takeover path
stops presenting `Authorization: Bearer <token>` to a port holder whose identity has not been
established, and a test proves a squatting local process receives no token.

Purpose: today `McpSupervisor.requestRemoteShutdownWithToken` (`McpSupervisor.kt:294-312`) hands the
MCP bearer token to whatever answers the port. That token grants full MCP tool access to the
operator's Burp — proxy history, repeater, intruder, scanner. Any local process that can bind
`127.0.0.1:<mcp port>` before Burp does can collect it.

Output: a proof-of-possession credential (`McpTakeoverProof`), a client that never puts the token on
the wire, a server that accepts the proof, and two new test suites — one proving the legitimate
takeover still works end to end, one standing up a fake listener that spoofs the identity header and
asserting no token reaches it.
</objective>

<named_assumptions>
Unresolved edges surfaced as explicit assumptions. Each carries a paired assertion that resolves it.

- **A-25-04 (clock).** The takeover client and the port holder are always on the same machine and
  therefore read the same `System.currentTimeMillis()`. No clock skew is possible, so a
  10-second window with a one-window fallback (max 20 s of validity) cannot mismatch for a
  legitimate takeover. *Paired assertion:* `McpTakeoverProofTest` asserts a proof minted at
  `t` validates at `t`, at `t + 9_999`, at `t + 10_001` (previous-window fallback) and is REJECTED
  at `t + 25_000`.
- **A-25-05 (host-string identity).** Client and server derive the proof from the same
  `McpSettings.host` string, because both read the same persisted preferences. If a user edits
  `host` between the old server binding and the new one starting (for example `localhost` ->
  `127.0.0.1`), the proof mismatches and takeover is rejected. That is a **safe** failure — the
  server stays down with an error log, and no credential leaks. *Paired assertion:*
  `McpTakeoverProofTest` asserts a proof minted for `localhost:PORT` is rejected against
  `127.0.0.1:PORT`, and Task 2 normalises the host with `trim().lowercase()` so casing alone never
  causes it. Recorded as a residual in ADR-16 (plan 25-03).
- **A-25-06 (server back-compat).** A **new** client talking to an **old** (v0.9.x) server gets 401
  on `/__mcp/shutdown`, because the old server only knows the bearer form. Outcome:
  `SHUTDOWN_REJECTED`, an error log, no retry, no credential on the wire. Accepted deliberately —
  degrading to "the server stays down and says so" is strictly better than leaking the token.
  *Paired assertion:* `McpTakeoverSquatterTest.aListenerThatRejectsTheProofYieldsShutdownRejected`
  drives a fake listener returning 401 and asserts the outcome enum.
</named_assumptions>

Present the decision below to the developer and record the answer verbatim in the plan SUMMARY. This

**The problem, stated precisely.** `requestRemoteShutdownWithToken` sends
`Authorization: Bearer ${settings.token}` (McpSupervisor.kt:301) to whatever holds the MCP port.
`probeExistingServer` (McpSupervisor.kt:255-292) establishes no identity that survives contact with
an attacker: in **local** mode it accepts a `X-Burp-AI-Agent: mcp` response header that any port
holder can echo, and in **external** mode it does not check the header at all — its verdict is
`alive && (settings.externalEnabled || header == "mcp")` at :285, so liveness alone gates the
takeover. The comment at :265-277 acknowledges the external-mode gap and defers real identity to
this phase.

**Option A — drop automatic takeover.** On a bind conflict, log and stop. Zero credential exposure.
Cost: after any unclean extension unload the MCP server stays down until the developer intervenes.

**Option B — server-supplied challenge/response.** A new pre-authentication endpoint returns a
nonce. Rejected on analysis, and the reason is concrete: any pre-auth response signal that only a
Burp AI Agent emits re-creates exactly the external-mode identification oracle that Phase 20's D-02
deliberately removed (KtorMcpServerManager.kt:200-205 withholds the identity header in external mode
so an unauthenticated scan cannot confirm what is behind the port).

**Option C — proof of possession (RECOMMENDED).** Stop having a secret to leak. The client presents
`HMAC-SHA256(key = token, message = "burp-ai-agent/mcp-takeover|v1|<host>:<port>|<10s window>")`
instead of the token. A non-holder learns nothing usable from it; a holder validates it in constant
time. Listener identity stops being load-bearing, because the credential is worthless to anyone who
does not already know the token. Adds no new endpoint and no new response signal, so D-02 is
untouched. Works in cleartext local mode, which is the default and which certificate pinning cannot
reach. Composes with plan 25-03, which pins the certificate where TLS is on and therefore restores
real listener identity for that configuration.

**Recommendation: Option C**, with plan 25-03's certificate pinning as the TLS-mode complement.
Together they answer SC1's "certificate-fingerprint pinning" and "challenge/response" alternatives
at once and keep automatic takeover working.

**Accepted residual under Option C** (must be read out with the recommendation, not buried): the
squatter does receive the *proof*. Within its 10-second window (plus one fallback window, so 20 s
worst case) that proof could be replayed to shut down the freshly-bound server — a denial of service
by a process that is already denying service by holding the port. Registered as T-25-04, disposition
`accept`.

If the developer selects **Option A** or **Option B**, STOP and return
`## CHECKPOINT REACHED — replan required`: Tasks 2 and 3 of this plan implement Option C only, and
plan 25-03's ADR text assumes it.
  </action>

  <behavior>
    - `McpTakeoverProof.forTarget(token, host, port, epochMillis)` returns a Base64-URL string with no padding, deterministic for a fixed window.
    - `accepts` returns true for a proof minted in the current window.
    - `accepts` returns true for a proof minted in the immediately previous window (the fallback that makes a window boundary crossing safe — A-25-04).
    - `accepts` returns false for a proof minted two or more windows ago.
    - `accepts` returns false when the token is blank, for every input, mirroring `isAuthorizedBearer`'s blank-token guard.
    - `accepts` returns false when the presented value is empty or is the token itself.
    - `accepts` returns false when the proof was minted for a different host or a different port (A-25-05).
    - Host comparison is case-insensitive and whitespace-insensitive; `LOCALHOST` and ` localhost ` mint the same proof as `localhost`.
  </behavior>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local process -> MCP listener port | Any local user can bind `127.0.0.1:<mcp port>`. Whoever holds it is untrusted, and the extension cannot tell from the socket who they are. |
| takeover client -> port holder | The extension initiates this call and, before this plan, presented a secret across it. This is the Finding 7 boundary. |
| MCP client -> MCP server routes | The existing SEC-04 access-control boundary. Unchanged by this plan; the shutdown route gains one additional accepted credential form and loses none. |

| T-25-01 | Information Disclosure | `McpSupervisor.requestRemoteShutdownWithToken` (`McpSupervisor.kt:301`) | critical | mitigate | Delete the `Authorization` request property; present `McpTakeoverProof.forTarget` instead. | T-25-03 | Spoofing | `X-Burp-AI-Agent: mcp` response header, local mode | high | mitigate | Same mitigation as T-25-02. The header is retained as a cheap filter and is explicitly demoted from control to hint, in the `McpSupervisor.kt:265-277` comment and in ADR-16 (plan 25-03). |
