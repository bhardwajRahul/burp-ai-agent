<objective>
Teach the logical-line composer that the open of a JSON string is a logical line start, and prove it
with a probe that fails first.

`logicalLineHeaderRule`'s escaped branch requires a preceding escaped newline. A header that is the
FIRST content of a JSON string value has neither a real line start nor a preceding escaped newline, so
**even the canonical `Cookie:` header survives STRICT there.** Round 3 measured it, and measured the
positive control firing on the same run, so this is a statement about the rule's reach and not a
broken fixture.

Purpose: the maintainer put this in scope for this round. It is the only gap in the set where the
CANONICAL spelling — not a variant, not an underscore, not a type — defeats the strongest privacy
mode. Reachable through `HttpRequestResponse.notes`, which carries analyst annotations, and through
any future field carrying a header fragment rather than a whole message.

Output: one new fixed-width lookbehind alternative, a red-then-green probe family on the real
serialized shape, an over-match bound, and the uncovered fourth start named rather than implied away.

**WHAT THIS PLAN MUST NOT DO.** It must not route `hostHeaderRegex` through the composer — that is
`AR-27-04`, it needs a human decision, and half of that fix produces a payload whose `request` is
anonymised and whose `url` is not. It must not widen `authHeaderRegex`'s NAME alternation — the vendor
class is `CONCERNS.md` W-A and stays open by prohibition. It must not fix the leading-whitespace /
obs-fold start: that is outside the maintainer's stated scope for this round and is filed instead. It
must not edit `RedactionTest`. It must not tick `REQUIREMENTS.md`.

**NO CHECKPOINT IS RAISED, for the reason plan 27-10 states.** Open questions go to
`27-HUMAN-UAT.md` via plan 27-13, legible as open.
</objective>
