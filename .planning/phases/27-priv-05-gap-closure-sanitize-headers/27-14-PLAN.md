<objective>
Close `27-VERIFICATION-4.md` **gap 1** — the one NEW defect round 4 shipped, and the only defect in
this phase's history that fails SAFE for privacy and breaks CORRECTNESS instead.

`JSON_STRING_OPEN = "\""` (`Redaction.kt:277`) is a BARE DOUBLE QUOTE presented as "the open of a
JSON string value". A double quote is not a JSON string open — it also occurs in HTML attributes, JS
string literals, quoted CSV fields and ordinary prose, all of which reach `Redaction.apply` through
seven consumers. All three composer-built rules inherit it, `authHeaderRegex` included. On the
primary serialized MCP emission path an escaped quote is consumed atomically by the value tail, so
the tail cannot terminate on any escaped quote and runs to the JSON string's real closing quote:
**1589 of 1714 characters destroyed, 40 of 40 content markers gone, and the JSON left structurally
valid so every existing shape assertion still passes.** The model silently receives a truncated
response body.

The fix is `JSON_STRING_OPEN = ":\""` — a JSON string VALUE open. Still fixed-width, so the cost
model is preserved verbatim. It was independently measured by BOTH `27-REVIEW-2.md` (CR-03) and
`27-VERIFICATION-4.md` (gap 1) to remove every false positive AND to keep both `notes`-carrier cases
closed. It is a real NARROWING and this plan names its cost rather than absorbing it: a JSON ARRAY
ELEMENT string open is then not a recognised start.

Purpose: this phase's own comment at `Redaction.kt:570-576` argues that removing analytically
load-bearing content from a security prompt is a functional regression. By that standard round 4
shipped one, on shipped 1.0.0 code, on the path the model actually reads. It leads round 5 because it
is live.

Output: one narrowed constant, two stated costs where a reader meets the rule, two repaired gates,
and one anti-drift source pin.

**THIS PLAN CLOSES NO REQUIREMENT.** Round 5 does not close PRIV-05. `REQUIREMENTS.md` must not be
edited by any task in this plan.
