<bytecode_facts_established_while_planning>
These were established by disassembling the exact dependency jars this build resolves
(`ktor-server-netty-jvm-3.1.3`, `ktor-server-core-jvm-3.1.3`, `okhttp-jvm-5.4.0`) plus one visibility
check against the Ktor 3.1.3 source. They are FACTS, not suggestions. Task 1 still measures the runtime
values, but it must not re-derive these and it must not contradict them.

1. **`call.request.headers[":authority"]` is ALWAYS null on HTTP/2. The accessor suggested in
   `20-VERIFICATION.md` does not work — do not use it.** `NettyHttp2ApplicationRequest` builds its
   `engineHeaders` lazily by iterating Netty's `Http2Headers` into a `HeadersBuilder`, but it SKIPS any
   entry whose name's first character is `:` (the bytecode reads `CharSequence.charAt(0)` and compares
   against `58`). Every HTTP/2 pseudo-header is filtered out of the Ktor headers map.

2. **The raw `Http2Headers` is unreachable from this project.** `NettyHttp2ApplicationRequest` is
   declared `internal` in the Ktor module (confirmed against the 3.1.3 source), so a Kotlin cast to it
   does not compile from our module regardless of what the bytecode's `public` flag suggests. Do not
   attempt it.

3. **The HTTP/2 `RequestConnectionPoint` DOES surface `:authority`.** For h2 the connection point is
   `Http2LocalConnectionPoint`, and its getters derive from `Http2Headers.authority()`: `serverHost` is
   the authority up to the FIRST `:`, falling back to the local socket host when `:authority` is absent;
   `serverPort` is the authority's port, falling back to the local socket port; `host` and `port` behave
   the same with `"localhost"` and default-port fallbacks; `version` returns the literal string `HTTP/2`.

4. **`Http2LocalConnectionPoint.serverPort` can THROW.** It calls `Integer.parseInt` on the substring
   after the first `:` with no surrounding exception handler, so an attacker-supplied `:authority` of
   `evil.example:abc` or `localhost:99999999999` raises `NumberFormatException` on a Netty event-loop
   thread. Any read of it from the gate must be guarded.

5. **On HTTP/1.1 the connection point ALSO falls back to the local socket.** `NettyConnectionPoint`
   derives `serverHost` from the `Host` header split on the LAST `:` (bracket-safe, unlike the h2 point),
   falling back to the local socket host when `Host` is absent. This is why the fallback must NOT be
   applied on HTTP/1.1: it would substitute the server's own loopback address for an absent `Host` and
   re-open the very fail-open being closed.

6. **`request.origin` is `request.local` here, but `local` is the safer read.**
   `ApplicationRequest.origin` resolves to
   `attributes.getOrNull(MutableOriginConnectionPointKey) ?: local`. `KtorMcpServerManager` installs only
   `CORS`, `McpAccessControl` and whatever `mcp {}` installs — no `ForwardedHeaders` /
   `XForwardedHeaders` — so the two are the same object today. Use `local`: `origin` becomes
   client-overridable through `X-Forwarded-Host` the moment anyone installs a forwarded-headers plugin,
   and a DNS-rebinding gate must not read a client-overridable authority.

7. **OkHttp drops a `Host` request header on HTTP/2.** `okhttp3.internal.http2.Http2ExchangeCodec`
   carries `host` in its skipped-request-header set alongside `connection`, `keep-alive`, `te`,
   `transfer-encoding`, `upgrade`, `proxy-connection` and `encoding`. Setting `Host` on an h2 request
   therefore proves nothing. The authority can only be forged through the request URL plus a `Dns`
   override that resolves the forged name to `127.0.0.1`.

8. **A bracketed IPv6 `:authority` cannot be reconstructed from the h2 connection point.** Because
   `serverHost` splits on the FIRST colon, `[::1]:9876` yields `[`. That is unrecoverable and will be
   denied. Record it as a residual; do not try to repair it.
</bytecode_facts_established_while_planning>

|----------|-------------|
| network client → Netty engine → gate | The request authority arrives as an HTTP/1 `Host` header or an HTTP/2 `:authority` pseudo-header; both are fully attacker-controlled and reach the gate through different engine paths |
