<objective>
Bound the audit sink for the two denial reasons an unauthenticated remote peer can trigger, and record
the decision that authorises doing so.

Purpose: phase 20 introduced a new primitive. In external mode every route but `/__mcp/health` answers
401, every one of those 401s is an `UNAUTHORIZED` or `BLANK_TOKEN` denial, and `report()` turns each one
into a synchronous `appendText` to `~/.burp-ai-agent/audit.jsonl` on a Netty event-loop thread. A peer
with no credential therefore controls the append rate to an unbounded file in the operator's home
directory, and buries genuine events under attacker-chosen noise — against a security tool's own audit
trail. D-09's window only ever covered the Output-tab line.

Output: ADR-13 in `DECISIONS.md`; per-reason coalescing of the two pre-authentication reasons into one
audit event per window carrying a `suppressed` count; per-occurrence emission preserved for the local-mode
reasons, which require local code execution to trigger; and the false accepted-risk rationale in the
reporter's KDoc replaced with an accurate one.
</objective>

<maintainer_decision_this_plan_implements>
The maintainer decided the shape of this fix. It is not open:

- **Rate-window ONLY the flood-capable reasons** — `BlockReason.UNAUTHORIZED` and
  `BlockReason.BLANK_TOKEN` — into one audit event per window carrying a `suppressed` count.
- **Keep per-occurrence emission for the local-mode reasons** (`ORIGIN_MISMATCH`, `HOST_MISMATCH`,
  `REFERER_MISMATCH`, `BROWSER_NO_ORIGIN`), which require local code execution to trigger.
- **Do NOT add size-capping or rotation to the shared `AuditLogger`.** That alternative was explicitly
  rejected as too broad for this gap closure. `AuditLogger` is not in this plan's `files_modified` and
  must not be edited.
- Because this moves D-06's literal "an audit event on EVERY occurrence", it **requires a recorded
  decision**: a new ADR-13 in the repo-root `DECISIONS.md`.
</maintainer_decision_this_plan_implements>

**`DECISIONS.md` format.** Repo root, currently 138 lines, latest entry is `## ADR-12: Per-session
token-budget guardrails via BudgetGuard (CAP-04)`. Every entry uses `## ADR-N: <title>` followed by
`**Context.**`, `**Decision.**`, `**Consequences.**` (the last as a bullet list). Append ADR-13 after
ADR-12 and match that shape exactly. Note the file's own header sentence: decisions "can be revisited …
but changing them should be intentional, not accidental" — this ADR is that intentional record.

**The reporter's real shape.** `McpBlockedRequestReporter` is an `internal class` taking
`logToOutput: (String) -> Unit` and `verboseAudit: Boolean = false`. Its members are `report`,
`buildPayload`, `auditValue`, `emitTransportTelemetry`, `maybeLogBlocked`, `blockedLine`,
`aggregateLine`, `outputValue`, `sanitize`, plus a private nested `data class ReasonWindow` holding two
`AtomicLong`s and a `windows` field declared `private val windows: MutableMap<BlockReason, ReasonWindow> =
ConcurrentHashMap()` — the declared type is `MutableMap`, the implementation is `ConcurrentHashMap`. Match
that style for the new map. `report()` currently calls
`emitTransportTelemetry(...)` and then `maybeLogBlocked(...)`, in that order.

**Do NOT share `ReasonWindow` instances between the two sinks.** `maybeLogBlocked` consumes the
suppression counter with `getAndSet(0L)`. If the audit sink read the same `ReasonWindow`, whichever sink
ran first would steal the other's count and both `suppressed` numbers would be wrong. The audit sink
needs its own map keyed by `BlockReason`.

**Runs on Netty event-loop threads.** No monitor lock, no scheduled executor, no blocking call. Keep the
existing lock-free read-then-CAS idiom; windows expire lazily on the next block for the same reason.
`0L` deliberately means "never logged" — do not introduce `Long.MIN_VALUE` arithmetic.

**detekt budget.** The class has 9 functions today; `TooManyFunctions` `thresholdInClasses` is 11, so add
at most two. `detekt.yml` overrides only `LongMethod`, `LongParameterList`, `MaxLineLength` and
`FunctionNaming`, so `ReturnCount` runs at its default max of 2. `detekt-baseline.xml` holds no entry for
this file and must stay byte-identical (QUAL-07). In the test source set, `TooManyFunctions` and
`MagicNumber` default to excluding test paths but `LongMethod` (project threshold 80) does not.
