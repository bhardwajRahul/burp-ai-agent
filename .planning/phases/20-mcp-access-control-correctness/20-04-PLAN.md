<objective>
Write the regression tests that would have caught the bypass.

The existing `KtorMcpServerManagerSecurityTest` was green throughout the live bypass because it invokes
`isAuthorized`, `constantTimeEquals` and `parseExternalCorsHosts` by reflection, in isolation. The
predicates were correct; they were simply never called. `McpServerIntegrationTest` was green because it
only exercises `/__mcp/shutdown`, which validates the token inside its own handler. These two tests must
exercise the PIPELINE, not the predicates.

They also carry the one end-to-end assertion that proves the blocked-request reporter is wired at all.
`McpBlockedRequestReporter` is fully unit-tested in Wave 1 and invoked only from `20-03`'s `onBlocked`
lambda; if that lambda were empty, four locked decisions (D-06, D-07, D-09, D-10) would ship as dead code
with every other check in this phase still green. The audit-event assertion in Task 1 closes that hole.

Purpose: SEC-04's own text says "the current `McpServerIntegrationTest` passes while the bypass is live,
so the new tests must fail against today's `KtorMcpServerManager`". The proof that they do is SC4, which
runs as its own serialised plan (`20-06`) so its transient file rollback cannot collide with any other
plan sharing the working tree.

Output: two real-server test classes.
</objective>
