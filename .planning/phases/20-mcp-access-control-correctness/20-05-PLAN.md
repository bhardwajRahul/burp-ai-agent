<objective>
Close the two consequences of D-02 that live outside `KtorMcpServerManager.kt`: the bind-conflict
takeover probe, which asserts on the header that just became local-only, and the user-facing runbook,
which promises a bearer check on every request that D-01 deliberately makes false.

`McpSupervisor.probeExistingServer` returns true only when the response is 2xx AND
`getHeaderField("X-Burp-AI-Agent") == "mcp"`. In external mode that header is now gone, so the probe
returns false, `attemptTakeover` returns `NO_COMPATIBLE_SERVER`, `handleBindFailure` logs "Port appears
busy and no compatible MCP server was detected for takeover" and schedules NO retry. That is a silent
functional regression in a code path with zero test coverage today —
`McpSupervisorRestartPolicyTest` fakes `McpTakeoverClient`, so the real `probeExistingServer` is never
exercised.

Scope fence: D-05 says Phase 20 PRESERVES takeover and Phase 25 (SEC-07) REWORKS it. This plan does the
minimum that keeps the local probe byte-identical and stops the external probe failing silently. It does
not redesign listener identity and it does not touch the token-disclosure path.

Purpose: SEC-04's D-02 half, and D-12.
Output: a mode-aware probe, its first test, and a corrected runbook.
</objective>
