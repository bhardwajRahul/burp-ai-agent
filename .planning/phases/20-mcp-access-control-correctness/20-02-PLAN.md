<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Gradle build script -> generated Kotlin source | Build-time string interpolated into compiled source; the value comes from `build.gradle.kts` itself, not from user input |
| test process -> filesystem | Test-generated TLS keystores are written to disk by `keytool` via `McpTls.resolve` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-13 | Information Disclosure | `GenerateBuildFlagsTask.version` | accept | The interpolated value is the project version from `build.gradle.kts:15`, not a secret and not attacker-influenced. Version disclosure over MCP is the intended SEC-05 5a behaviour |
| T-20-14 | Tampering | test TLS keystore path | mitigate | `externalTlsSettings` requires a caller-supplied `Path` from `Files.createTempDirectory(...)`; a test must never be able to auto-generate over `~/.burp-ai-agent/certs`, and the file carries an explicit comment saying so |
| T-20-15 | Spoofing | `trustAllClient` | accept | Trust-all TLS is confined to the test source set against a loopback server the test itself started. It is never reachable from `src/main`; `McpSupervisor.kt:22-26`'s loopback-only trust override is the production analog and is untouched |
| T-20-SC | Tampering | package installs | accept | No package-manager install in this plan. `20-RESEARCH.md` section "Package Legitimacy Audit" records zero new dependencies; the task explicitly asserts `build.gradle.kts`'s okhttp line count is unchanged |
</threat_model>
