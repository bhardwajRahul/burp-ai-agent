  <name>Task 2: Confirm the E8 settings-atomicity answer — accepted residual, or mutual exclusion</name>

  <decision>
How should Phase 23 answer AI-SPEC dimension E8 — the half-applied settings set that a tool worker can
newly observe once D-05 and D-11 remove the EDT serialisation?
  </decision>

  <context>
`applyAndSaveSettings` performs about ten independent mutations with no transaction. Today EDT
serialisation makes it mutually exclusive with chat tool execution by construction; D-05 and D-11
remove that edge, so a tool worker can observe a **half-applied** settings set. AI-SPEC dimension E8
assigns this call to the maintainer-as-practitioner. It passes on any of the three answers **provided
one is chosen and pinned by a test**; it fails only if the interleave is reachable with no decision
recorded anywhere.

**What research established, so the choice is made on facts rather than on fear.**

Every field involved is `@Volatile`, so this is **atomicity**, not visibility. (`AuditLogger.enabled`
is `@Volatile` at `AuditLogger.kt:33-34` — an earlier claim that it was not has been checked and is
false.) And `McpToolContext` is an **immutable data-class snapshot already built on the EDT before
dispatch** at every call site (`McpToolContext.kt:19-48`; `ChatPanel.buildToolContext` at
`ChatPanel.kt:3005-3023`), carrying `privacyMode`, `hostSalt`, `toolToggles`, `unsafeEnabled`,
`enabledUnsafeTools`, `maxBodyBytes` and `edition`. **Snapshot-before-dispatch is therefore already
the shipped architecture for everything the context carries** — there is nothing to build for that
half, and nowhere left to tighten it.

The entire reachable half-applied state is narrow and nameable: *the `privacyMode` snapshotted before
the save, combined with the custom-pattern set current at execution* (or the converse).
`Redaction.setCustomPatterns` assigns a whole new `List<Pattern>` to a `@Volatile` field
(`Redaction.kt:769-789`), so the pattern list is never partially compiled. Every combination is a
valid mode paired with a valid, fully-published pattern list. **There is no state in which a call is
redacted under no rules.**
  </context>

  <options>
    <option id="documented-residual">
      <name>A — RECOMMENDED: accept the residual, document it, and pin it with scenario S-11</name>
      <pros>Adds no lock and no new failure mode. Records the window in the SUMMARY and in a comment at the dispatch site, keeps the two privacy-relevant global writes contiguous so it is one readable block, corrects the stale `Redaction` comment, and adds an interleave test that goes red if a future refactor makes the worker read live settings instead of its snapshot. E8's PASS clause asks for a recorded decision plus a test; this delivers both.</pros>
      <cons>One narrow interleave stays reachable: a snapshot privacy mode from before the save paired with the custom-pattern set from after it. Both halves are individually valid and fully published, but the pairing is not transactional.</cons>
    </option>
    <option id="mutual-exclusion">
      <name>B — mutual exclusion: a lock held across applyAndSaveSettings</name>
