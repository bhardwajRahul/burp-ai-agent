Wire ONE path — an approved chain tool call — from the EDT, through a daemon worker, back to the EDT,

**1. Create `src/main/kotlin/com/six2dez/burp/aiagent/ui/OffEdtDispatch.kt`.**

Declare `internal object OffEdtDispatch` in package `com.six2dez.burp.aiagent.ui`. It carries:

- `@Volatile private var settledObserver: ((String) -> Unit)? = null` and
  `fun registerSettledObserver(observer: ((String) -> Unit)?)`. Nullable-accepting, so passing `null`
  is the clear. KDoc must state that the hook is null in production, exists for tests, and follows
  `AuditLogger.registerGlobalEmitter`'s install/clear discipline.
- `fun <T> run(threadName: String, label: String, logError: (String) -> Unit, work: () -> T, onEdt: (Result<T>) -> Unit)`.
  Assign to a local named exactly `body` a `Runnable` that: evaluates `runCatching(work)`; on failure
  calls `logError` with a message carrying `label` and the throwable; then posts a single
  `SwingUtilities.invokeLater` that invokes `onEdt(outcome)` inside a `try`, routes any escaping
  `Throwable` to `logError`, and in a `finally` invokes `settledObserver` with `label`. That local's
  **name is pinned by an acceptance criterion** — do not call it `task`, `runnable` or `work`. Start it
  with `Thread(body, threadName).apply { isDaemon = true }.start()`.

Three properties to assert, not assume: the daemon flag is set **explicitly**; the thread carries a
name so a stuck worker is identifiable in a thread dump; and the observer fires from a `finally`, so
it still fires when `onEdt` itself throws. `MainTab.kt:193` sets no daemon flag — copy its *idiom*,
copy `MontoyaHttpTransport.kt:85`'s *form*.

The `Result<T>` crosses the thread boundary **intact**. Do not unwrap it, do not stringify a throwable
on the worker: `reportFailedToolCall` (`ChatPanel.kt:2936`) needs a real `Throwable` for its
`errorClass` key.

After the dispatch statement, `run` returns immediately. `MontoyaHttpTransport.execute` is the in-repo
counter-example — it offloads and then makes the calling thread wait for the worker's result, which
dodges Burp's exception while leaving the UI frozen. Read `MontoyaHttpTransport.kt:84-90` and do not
reproduce that shape anywhere in this phase.

Use `java.util.concurrent` and JDK Swing only. Coroutines are forbidden outside the `mcp` package
(CONVENTIONS.md:95), `SwingWorker` is a new concurrency idiom SC6 warns against, and D-05 already
rejected a `ChatPanel`-owned `ExecutorService`.

**Do not name either rejected idiom in a comment in this file, or in any file under
`ui/`.** `23-05` closes SC6 by negative-grepping that whole package for those two identifiers, and a
comment proudly recording that you did not use one is textually indistinguishable from using it — it
would fail the phase gate for the opposite of the reason the gate exists. Say what the code *does*
(a named daemon `Thread` plus one `SwingUtilities.invokeLater`, the `MainTab` idiom) and cite
CONVENTIONS.md:95 and D-05 by reference.

**4. `ChatPanel.kt` — restructure `executeApprovedToolCall` (`:2841`).**

*(a) Capture, on the EDT.* Introduce a private `data class ToolCallCapture` holding everything the
worker or the tail needs: `sessionId`, `userText`, `call`, `panel`, `context`, `backendId`,
`chainStep`, `canonicalId`, `knownTool`, `tier`, `decision`, `origin`, `traceId`,
`remainingToolIterations`, `startedAt`. A capture record rather than a wide helper signature is
deliberate: `detekt.yml` sets `LongParameterList` thresholds at 10/10, and a helper taking ten
captured values sits on the edge.

Place an inline comment immediately after the capture block marking the last EDT read of guarded
state, in the house style that names the requirement and the failure it prevents (AI-SPEC E5:
the worker must read none of `sessionPanels`, `sessionStates`, `sessionsById`, `sessionDrafts`,
`pendingDecisions`).

*(b) Enter S3 and dispatch.* Call `setSendingState(true)` (D-06 / UI-SPEC Rule S-2), create
`val token = Any()`, `runningTool.set(token)`, then `OffEdtDispatch.run(...)` with
`threadName = "burp-ai-tool-exec"`, `label = captured.traceId`,
`logError = { api.logging().logToError(it) }`,
`work = { McpToolExecutor.executeTool(call.tool, call.argsJson, captured.context, approved.origin) }`,
and `onEdt = { result -> finishApprovedToolCall(captured, token, result, onCompleted) }`. Return
`ToolCallOutcome.EXECUTING`.

`label = traceId` is deliberate and carries a Phase 22 lesson forward (commit `ab55ff5`,
*"make the SC3 metadata assertion select by trace id, not by position"*): an ordering assertion keyed
on identity reports a reordering bug; one keyed on list position hides it.

*(c) Extract the EDT tail* into a new `private fun finishApprovedToolCall(captured, token, result, onCompleted)`.
Extraction is mandatory, not stylistic: `executeApprovedToolCall` is ~83 source lines and carries **no**
`LongMethod` baseline entry, while `detekt.yml` sets the threshold at 80. Inlining a worker plus a tail
would cross it and add a baseline entry, and `detekt-baseline.xml` is pinned at 1096 as a v0.10.0
milestone metric (STATE.md:56-58).
