Close the two Critical review findings that live in the code Phase 23 wrote, one of which falsifies a
must-have plan 23-01 claimed to deliver.

Purpose: `23-01-PLAN.md`'s `must_haves.truths` asserts *"S3 is global to `ChatPanel`, so a second
dispatch cannot be started from the UI while the first is live."* It is not true. `setSendingState`
(`ChatPanel.kt:1011-1016`) toggles only `sendBtn.isVisible`, `cancelBtn.isVisible` and
`inputArea.isEnabled`; `toolsBtn` is gated purely on `mcpAvailable` (`:346`) and `openToolDialog`
(`:1070`) has no re-entrancy check at all. A second dialog tool overwrites `runningTool`, and the first
worker's `finishUserOriginatedToolCall` then returns having rendered nothing and logged nothing — the
user is given no indication the call happened, no indication it was discarded, and no way to recover
the answer. Its tail's unconditional `setSendingState(false)` also clears an unrelated in-flight backend
turn's busy state. That is **CR-05**, and it is a plan-fulfilment gap rather than merely new scope.

Measured while scouting and NOT in the review: the same root cause has a second, easier limb.
`updateChatAvailability` (`:343-350`) writes `inputArea.isEnabled = mcpAvailable` and
`toolsBtn.isEnabled = mcpAvailable`, ignoring the busy state entirely — and `MainTab.mcpStatusTimer`
(`MainTab.kt:81-88`) fires `updateMcpControls()` every **1000 ms**, which calls
`chatPanel.setMcpAvailable(running)` (`MainTab.kt:583`). So today, one second into ANY tool run, the S3
disabled input area and the tool button are both silently re-enabled by a timer, with no second dialog
needed. Plan 23-06 makes this fire at a new moment as well, by moving `renderStatus()` into an
asynchronous tail. Both plans are in this wave; this plan owns the fix.

**CR-04** is the third item: `OffEdtDispatch.kt:93-95`'s failure-path `logError` is unguarded and sits
on the path to the `invokeLater`. A throwing sink kills the runnable, the tail never runs, and the panel
is stranded in S3 for the rest of the Burp session with nothing running.

Output: a busy seam that actually holds, an audit record for a discarded user-originated call, and a
dispatcher whose tail cannot be lost to a logger.

**`assertEdt()` is not touched.** **D-14 is not touched** — this plan reaches no MCP supervisor code.
</objective>
