owned by an unloaded extension's classloader** — a local listener with no live extension behind
SEC-04's access-control checks — plus re-enabled scanners with nothing behind them. Before this phase
the save body ran on the EDT and so did the unload path, which made the interleave impossible. This is
a defect the offload created.

Phase 23 gave `ChatPanel`'s tool worker a supersede for exactly this class of problem (D-08, four
teardown exits). The Settings worker has none. This plan gives it the same shape.

<anti_vacuity_mandate>
Five tests in this phase were found green while the defect under test was fully present, every one
caught by a red probe and none by review.

**Every new or changed assertion is accepted only after it has been driven RED:** reverse exactly ONE
statement in the production source (never `git stash` — banned in this repo; never revert the test),
run the suite, record the failing test name and line number, restore, and confirm `git diff` on that
file is empty. Each red probe below is a first-class step with its own acceptance criterion.

**The trap this plan is most exposed to, and it is the sharpest one in the phase.** Every assertion
here is of the form *"this call never happened"* — `verify(mcpSupervisor, never()).applySettings(...)`.
After an asynchronous dispatch a bare `never()` passes **vacuously and faster** than it would with the
bug absent, because the worker simply has not reached the call yet. Two defences are mandatory on every
such assertion in this plan:

1. **Await the settle record before verifying.** `OffEdtDispatch`'s settle observer fires from the EDT
   tail's `finally`, so a successful `settledSignal.await(...)` means the body has finished or
   returned. Assert the await's boolean result with a message, never call it bare.
2. **Carry a paired positive control in the same task.** For every "never called under supersede" test
   there must be a sibling test proving the same call IS made when no supersede lands, using the same
   fixture and the same latch shape. A `never()` with no positive control is an assertion that cannot
   distinguish "guarded" from "never wired at all".

**Other traps measured in this codebase:**

- A test asserting NO work happened must read the record written synchronously with the dispatch
  (`dispatchedLabels()`), never the settle record, when the claim is about a worker STARTING. Here the
  claim is about a call inside a worker that did start, so the settle record is the correct read — but
  only with defence 1 above.
- STRICT redaction has a built-in `token=…` rule, so a marker containing `token=` is redacted
  regardless of the code under test.
- `grep -c` counts the comment you just wrote explaining the gate. Filter with
  `grep -v '^[[:space:]]*\(//\|\*\|/\*\)'` before counting in Kotlin or Gradle — **block comments
  included, not only `//`**, because this plan instructs you to write KDoc that names the very
  identifiers the counts assert on, and a KDoc line survives a `//`-only filter. Use
  `grep -v '^[[:space:]]*#'` in YAML, which has no block comments.
</anti_vacuity_mandate>
