Create `src/main/kotlin/com/six2dez/burp/aiagent/ui/SettingsPersistQueue.kt` declaring
`internal class SettingsPersistQueue(private val logError: (String) -> Unit)`.

State, all `java.util.concurrent` plus JDK — no executor, no pool, no coroutines (SC6, D-05,
CONVENTIONS.md:95):
- `private val submitted = AtomicLong(0)` — monotonic generation, minted on the calling thread.
- `private val applied = AtomicLong(0)` — highest generation whose apply has begun.
- `private val lock = ReentrantLock()` — serialises apply bodies so a write is applied whole.
- `@Volatile private var disposed = false`.

Public surface:
- `fun submit(label: String, snapshot: AgentSettings, apply: (AgentSettings) -> Unit, onSettled: (Result<Unit>) -> Unit)`.
  Call it from the EDT with a snapshot already read off the Swing components. It mints
  `val generation = submitted.incrementAndGet()` as its FIRST statement, on the calling thread — the
  same placement rule and the same reason as `OffEdtDispatch`'s `dispatchedObserver`: submission order
  must be click order, not thread-start order. It then calls `OffEdtDispatch.run` with
  `threadName = "burp-ai-settings-sync"`, `label = "$label-$generation"`, `logError = logError`,
  `work = { applyIfCurrent(generation, snapshot, apply) }`, `onEdt = onSettled`.
- `fun dispose()` — sets `disposed = true` and nothing else. It must NOT take `lock`: a worker inside a
  bounded 10-second `mcpSupervisor.applySettings` holds it, and a lock-taking `dispose()` called from
  `MainTab.shutdown()` on the EDT would reintroduce the exact freeze this phase exists to remove. State
  that bound in the KDoc honestly — `dispose()` guarantees that no NEW apply starts, not that an
  in-flight one is stopped.

Private `applyIfCurrent(generation, snapshot, apply)`:
`lock.withLock { if (disposed) return; if (generation <= applied.get()) return; applied.set(generation); apply(snapshot) }`.
`applied` is advanced BEFORE `apply` runs, so a throwing older write cannot be retried over a newer
one. Document that ordering choice inline.
