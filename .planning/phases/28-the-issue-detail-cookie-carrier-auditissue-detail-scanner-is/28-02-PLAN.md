<objective>
Resolve `InjectionPointExtractor.kt:29` in the same phase as the route it feeds, and PROVE the
already-controlled consumer is byte-unchanged rather than asserting it.

Purpose: phase 27 refused this conversion on the record, and gave the reason in source at

"a tidier file and an unchanged leak", making the route LOOK addressed. Plan 28-01 removed that
objection by controlling the route. This plan collects the conversion and, critically, closes the

Output: one cookie-type predicate in the tree instead of two, a derived count rather than a restated
one, and a named assertion protecting the un-double-redacted consumer.
</objective>

<design_decision id="D-28-02" title="SC4's double-redaction boundary: route-specific, not predicate-wide">
**Chosen:** the control from plan 28-01 lives at CONSUMER 2 (`ActiveAiScanner.createConfirmedIssue`)
ONLY. `InjectionPointExtractor.extract` keeps returning the RAW cookie value. The extractor's
`:29` predicate is resolved by IDENTITY — swapping a hand-written type-name equality for the shared
`Redaction.isCookieParameterType` — which is provably value-preserving and changes no disposition.

**Why:** the predicate has two consumers with different dispositions.
`AdaptivePayloadEngine.kt:52` is ALREADY CONTROLLED — it substitutes its own value marker under any
non-`OFF` mode. `ActiveAiScanner.kt:1239` was UNCONTROLLED and is the finding. A predicate-wide fix
(redacting inside `extract`) would hit both, and redacting the controlled path a second time yields
a prompt in which the model is told a value was redacted twice by two different vocabularies —
misleading, and it destroys the attribution that makes each route's control independently testable.
The roadmap states the failure mode directly: the predicate is only meaningful as part of the route
it feeds.

**Rejected — redact inside `InjectionPointExtractor.extract`:** one line, looks like the tidy fix,
and it is the exact failure this phase exists to avoid. It also silently changes what the SCANNER
sends as a payload baseline, because `InjectionPoint.originalValue` is scanner input and not only a
reporting field.

**Rejected — leave `:29` alone and fix only the route:** would satisfy SC1-SC3 and fail SC4. The
roadmap pairs them deliberately, and `26-SECURITY.md` T-26-02-01 records the make-it-look-addressed
failure three times.

**PROOF STRATEGY, because the roadmap requires proof and not assertion.** Byte-unchangedness of the
controlled path is established by composition, with both halves machine-checked:
(a) `AdaptivePayloadEngine.kt` is byte-unchanged across the entire phase — checkable with
`git diff`, and it appears in no plan's `files_modified`;
(b) the extractor still hands it the RAW value — checkable by a behavioural test asserting
`extract` returns the raw parameter value for a COOKIE-typed parameter.
Unchanged input plus unchanged code is byte-identical output. Task 2 adds a third, direct
confirmation by capturing the actual prompt.

Reversibility: reversible. The conversion is an identity swap and the control site is unchanged.
</design_decision>
